# AI Content Reviewer

An offline, installable app that scans files for **AI-generation identifiers** and shows exactly why each one was flagged. Drop in documents, spreadsheets, slides, PDFs, images, source code or whole ZIP archives. Everything runs in your browser, nothing is uploaded, and it keeps working with no internet connection.

Meet **Lens**, the 3D mascot. It reacts to what's happening: it scans, celebrates clean files, raises the alarm on AI fingerprints, shrugs on a 404 and falls asleep when the library is empty.

## What it detects

| Category | Examples | Strength |
| --- | --- | --- |
| Visible watermarks (pixels) | Gemini / Nano Banana ✦ sparkle (alpha-map matching with reverse-blend verification, all known sizes and margins, robust to JPEG re-saves and resizing), DALL·E colour bar | Strong / moderate |
| Provenance & Content Credentials | C2PA/JUMBF manifests, IPTC `DigitalSourceType = trainedAlgorithmicMedia`, IPTC AI-system/prompt fields | Strong |
| Generator fingerprints | Stable Diffusion/ComfyUI/InvokeAI prompts and seeds in PNG chunks, Midjourney job IDs, DALL·E/Firefly/Gemini in EXIF/XMP/IPTC-IIM, xAI Grok EXIF signatures, China TC260 `AIGC` labels (Doubao, Jimeng, Kling, Qwen, Hunyuan…), Gamma/ChatGPT/Copilot in PDF and Office properties, Copilot as document author | Strong |
| Chatbot residue | ChatGPT `【4†source】` and `oaicite` tokens, `utm_source=chatgpt.com` links, "As an AI language model", chat-UI text, unfilled `[Insert …]` placeholders | Strong / moderate |
| Spreadsheet AI functions | `=COPILOT()`, `=GPT()`, `=AI()`, `=OPENAI()` (including `_xlfn.` storage form) | Strong |
| Code & repositories | "Generated by Copilot/Claude Code", `Co-Authored-By` AI trailers, `.cursorrules`, `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`, `.aider*`, `.windsurfrules` | Strong |
| Hidden characters | Zero-width spaces/joiners and other invisible Unicode (emoji ZWJ sequences and leading BOMs excluded) | Moderate / weak |
| Writing style | Sentence-length burstiness, AI-favoured vocabulary, stock phrases, em-dash density, uniform paragraphs | Weak/moderate, capped so style alone can never reach "Strong" |
| Context | Real camera EXIF (make, lens, exposure) is shown as a counter-signal | Info only |

Archives are opened recursively (up to 5 levels), and images embedded in DOCX/PPTX/XLSX are scanned too. Zip-bomb, size and entry-count guards apply.

**Verdicts:** `Strong evidence` (needs a hard identifier) · `Likely AI` · `Possible signals` · `No AI signals`. Each file gets a 0–100 score from a probabilistic combination of findings, and every finding comes with highlighted evidence, its location and a "why this matters" explanation.

**How the Gemini sparkle check works:** the bottom-right corner is decoded (in a worker via `OffscreenCanvas`, a main-thread canvas on older Safari, or a built-in PNG decoder) and searched for Gemini's measured alpha maps at every plausible size and margin. A candidate counts only if it matches the shape *and* reverse-blending it (`original = (observed − α·255)/(1 − α)`) makes the star's edges vanish in every colour channel. On 29 real Gemini outputs it finds 25 (21 strong). On 200 clean photos and textures at Gemini output sizes, including JPEG re-saves, it raised no flags. Cropped-out or heavily edited marks can't be seen, and a Gemini image without the mark (Ultra tier, API output, mark turned off) only shows up through its metadata.

> **Signals, not proof.** Identifiers are easy to strip (cropping, screenshots, re-saving, copy-paste into a new file), so "No AI signals" never guarantees human authorship. C2PA signatures are recognised but not cryptographically verified offline. Invisible pixel watermarks (Google SynthID, Meta, OpenAI) can only be verified by their owners. For SynthID, ask the Gemini app "Was this made with Google AI?". Text-only visible labels such as `豆包AI生成` or Meta's "Imagined with AI" would need OCR, which isn't included.

## Supported formats

DOCX, XLSX, PPTX, ODT/ODS/ODP, PDF, PNG, JPEG, WebP, GIF, TIFF, HEIC/AVIF (metadata), ZIP/EPUB/JAR, Jupyter notebooks, HTML, Markdown, plain text, CSV/JSON, 40+ source-code languages (including PL/SQL), audio/video metadata (ID3/MP4), and legacy .doc/.xls (string scan only). 7z/RAR/tar.gz aren't unpacked; convert them to ZIP first.

## Install and use

- **Web / PWA:** open the GitHub Pages site and click **Install** (Chrome, Edge, Android), or use **Share → Add to Home Screen** on iPhone/iPad. After the first load it runs fully offline.
- **Single file:** download `AI-Content-Reviewer.html` from [Releases](../../releases) and double-click it. No install, no server, works on air-gapped machines.
- Add files by drag-and-drop (anywhere on the page, folders included), the file picker, **Scan a folder**, or paste (files or text) with Ctrl/⌘+V. **Try sample files** loads synthetic examples of each detector.

## Storage

Originals are stored in IndexedDB as 4 MB chunks, so large files can be reviewed, re-scanned (for example after a rules update) and downloaded later without re-uploading. Results are stored next to them. The Library shows storage usage and requests persistent storage for large files. You can turn off "Keep files in Library" in the Guide.

## Development

```bash
npm install
npm run dev          # local dev server
npm test             # detector + engine tests (vitest, Node)
npm run build        # PWA build → dist/
npm run build:single # single-file build → dist-single/AI-Content-Reviewer.html
```

Architecture:

- `src/scan/` is the detection engine: pure JS that runs in a Web Worker pool in the app and in Node for tests. It includes a streaming ZIP reader on `Blob.slice` + `DecompressionStream`, hand-written PNG/JPEG/EXIF/XMP/C2PA parsers, OOXML/ODF extractors, and pdf.js (legacy build, in-worker) for PDFs. Signatures live in `src/scan/rules.js` (versioned).
- `src/avatar/` holds Lens, a procedural three.js character (no model files) with 13 states, plus an SVG fallback used when WebGL is unavailable, reduced motion is on, or the "Simple" mascot is chosen.
- `src/store/db.js` is the IndexedDB layer. `src/app/store.js` handles state and scan orchestration.
- `src/ui/`, `src/views/` and `src/styles/` are the vanilla JS UI and the design system (dark/light tokens, responsive from 360 px phones to desktop, keyboard and screen-reader support).

Screenshot/test hooks: `?avatar=<state>` pins the mascot state, and `?nowebgl` forces the SVG fallback.

## Deployment

- `.github/workflows/pages.yml` builds, tests and deploys to GitHub Pages on pushes to `main`. Enable it once under **Settings → Pages → Source: GitHub Actions**.
- `.github/workflows/release.yml` attaches the single-file HTML and a zipped web build to a GitHub Release when you push a `v*` tag.
